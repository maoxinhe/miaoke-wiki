# 提示词工程

> 提示词的质量决定 AI 输出质量。本节给出可复用的方法与模板。

## 高质量提示词四要素

| 要素 | 说明 | 示例 |
| --- | --- | --- |
| 角色 | 告诉模型扮演什么身份 | 「你是资深运维工程师」 |
| 任务 | 明确要做什么 | 「分析下面的报错并给出排查步骤」 |
| 约束 | 限定格式、长度、语气 | 「用 5 步，每步一行命令」 |
| 输入 | 提供必要上下文/材料 | 附上报错日志原文 |

## 通用模板

```text
【角色】你是<角色>
【任务】请<具体任务>
【要求】<格式 / 长度 / 语气约束>
【背景】<必要上下文>
【材料】<待处理内容>
```

## 常见技巧

- **拆解问题**：复杂任务拆成多个小步骤，逐步提问。
- **多轮追问**：先给草稿，再要求修改，比一次性要求更有效。
- **给出示例**（few-shot）：给一两个期望输出示例，模型更容易对齐。
- **明确否定**：明确「不要做 X」，减少错误倾向。
- **请求复核**：要求「列出不确定性」「标注不确定项」，减少幻觉。

## 反模式（避免）

| 反模式 | 问题 |
| --- | --- |
| 提示词含糊 | 输出泛泛而谈，无法落地 |
| 一次要求过多 | 顾此失彼，输出质量下降 |
| 盲目信任输出 | 关键事实未经核验 |
| 机密信息入提示词 | 可能违反数据合规 |

## 示例速查

| 场景 | 模板要点 |
| --- | --- |
| 写周报 | 给角色+材料，要求按「进展/问题/计划」结构 |
| 排查报错 | 附报错原文，要求分步排查并给命令 |
| 写文案 | 给目标读者+语气，要求多版本 |
| 代码助手 | 给需求+技术栈+约束，要求可运行代码 |
