# API 与集成

> 面向开发与集成团队，说明如何把大模型能力接入业务系统。**API 密钥、内网地址一律不写入本站**。

## 接入流程

1. **选型**：确定模型/服务商与计费方式（参考「工具与平台」）。
2. **申请密钥**：通过统一渠道申请，登记用途与负责人。
3. **环境隔离**：密钥存于环境变量 / 配置中心，区分 `测试` 与 `生产`。
4. **联调**：先用最小用例验证返回与错误处理。
5. **上线**：加入监控（调用量、延迟、错误率）、限流与降级。

## 关键设计要点

| 关注点 | 说明 |
| --- | --- |
| 错误处理 | 处理超时、限流（429）、上下文超限（400/413）等 |
| 重试与退避 | 对瞬时错误做有上限的指数退避重试 |
| 缓存 | 对可复用结果做缓存，降成本提速度 |
| 超时控制 | 给每次调用设置合理超时，避免拖垮主流程 |
| 降级 | 模型不可用时回退到兜底逻辑，不影响核心功能 |
| 成本控制 | 监控 Token 消耗，设置阈值告警 |

## 安全红线

- 密钥严禁硬编码进代码、提交仓库或写入文档。
- 用户输入可能包含注入内容，进行必要的输入校验与提示词防护。
- 涉及敏感 / 个人信息的数据，先做合规评估与脱敏。

## 参考代码结构（示意）

```js
// 伪代码：带超时与错误处理的调用封装
async function callLLM(prompt, options = {}) {
  try {
    const res = await fetch(API_URL, {
      method: 'POST',
      headers: { Authorization: `Bearer ${process.env.API_KEY}` },
      body: JSON.stringify({ model, messages: [...], ...options })
    })
    if (!res.ok) throw new Error(`HTTP ${res.status}`)
    return await res.json()
  } catch (e) {
    // 记录日志、按需重试、触发告警
    throw e
  }
}
```
