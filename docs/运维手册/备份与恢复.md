# 备份与恢复

> 备份的意义在于**能恢复**。请定期演练恢复流程，不要等到灾难发生才发现备份不可用。

## 备份对象与策略

| 对象 | 备份方式 | 频率 | 保留周期 | 存放位置 | 状态 |
| --- | --- | --- | --- | --- | --- |
| 数据库 | 逻辑/物理备份 | 每日 | （待定） | 异地/对象存储 | 待接入 |
| 配置文件 | 版本库 | 每次变更 | 永久 | Git 仓库 | 待接入 |
| 上传文件/附件 | 对象存储同步 | 实时/每日 | （待定） | 对象存储 | 待接入 |
| 网站/应用代码 | 版本库 | 每次提交 | 永久 | Git 仓库 | 待接入 |

## 备份规范

- **3-2-1 原则**：至少 3 份数据、2 种介质、1 份异地存储。
- 备份文件加密存放，访问受控。
- 定期校验备份完整性（能读、能恢复），而不只是「备份任务成功了」。

## 恢复流程（通用）

1. 确认恢复目标时间点与恢复范围。
2. 从备份介质取回备份。
3. 在测试环境先行演练恢复，确认无碍后再对生产恢复。
4. 恢复后做完整性校验（数据量、抽样数据、业务功能）。
5. 记录恢复耗时与结果，评估是否需要缩短备份间隔。
