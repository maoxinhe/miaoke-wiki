# 微办公系统 · 运维知识

> 本文档为团队自建「微办公系统」的运维与部署规范。**所有密钥、Token、密码一律使用占位符，真实值存放于私有配置**。

## 一、项目概览

- **项目名称**：微办公系统（`office.camzy.tech`）
- **用途**：内部办公协作平台，一套系统搞定——文档管理、PDF 阅读、在线表格、问卷/调查、公告、待办、审批、日程日历、任务看板、通讯录、员工管理，员工独立账号。
- **一句话说明**：轻量自建微办公，内部办公用独立账号登录，问卷与公开文档对外可访问。
- **技术栈**：Node.js + Express + node:sqlite（`DatabaseSync`），前端原生 HTML/CSS/JS，pm2 进程管理，serv00 平台 + devil 反代。
- **依赖**：无第三方付费服务；数据库为 SQLite 单文件。
- **主要负责人**：CAMZY（联系方式见团队通讯录）。

## 二、运维注意事项

### 1. 运行环境

- **服务器**：serv00（`<服务器地址>:22`，SSH 用户 `<服务器用户>`）
- **应用目录**：`<服务器用户>/office-app/`（含 `server.js`、`public/`、`data/office.db`、`uploads/`、`node_modules/`）
- **端口**：`11215`（内网，由 devil 反代到公网）
- **域名**：`https://office.camzy.tech`（证书 Let's Encrypt）
- **环境变量**：见私有配置（`<你的密钥在私有配置>`）。涉及 SSH 密码、DNS/云厂商 Token、SecretKey 一律存私有配置，**禁止进代码库明文**。

### 2. 启动与停止

```bash
export PATH=$HOME/.npm-global/bin:$PATH
pm2 restart office        # 重启
pm2 stop office           # 停止
pm2 start office          # 启动
pm2 logs office           # 看日志
```

### 3. 部署与发布

1. 本地改代码 → `node --check server.js`、`node --check public/js/app.js` 语法校验。
2. 打包（排除 `node_modules`、`data`、`uploads`、`_backup`）→ 上传服务器 → 解压覆盖（**保留 `data/`、`uploads/` 不覆盖**）→ `pm2 restart office`。
3. 发布前先备份：`cp server.js server_backup_<版本>.js`。
4. 回滚：用备份文件还原 `server.js` / `public/`，重启即可；**数据库文件不覆盖**，避免丢数据。

### 4. 监控与告警

- **关键指标**：`pm2 list` 看进程 online 状态与内存；`curl -s -o /dev/null -w '%{http_code}' https://office.camzy.tech/` 看是否 200。
- **日志**：`pm2 logs office`。
- **告警**：页面打不开、登录返回非 200、内存持续超配额时人工介入（暂无自动告警，待核对是否接入）。

### 5. 数据与存储

- **数据库**：`data/office.db`（单文件，表自动建 + `ensureCol()` 轻量迁移，加列无需手改 schema）。
- **上传文件**：`uploads/` 目录（软删除后仍留物理文件，彻底删除才移除）。
- **备份**：定期整体打包 `data/` 与 `uploads/`；恢复时直接覆盖对应目录后重启。

### 6. 安全红线

- 密钥、Token、密码一律存私有配置，禁止明文输出/入库。
- 涉及外部账号、仓库、云盘写入，先经授权。
- 故障应急联系：CAMZY（见通讯录）。
