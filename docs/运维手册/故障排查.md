# 故障排查手册

> 排查思路：**先止血、再定位、后根治**。以下按「现象 → 排查 → 处置」组织，供团队快速对照。

## 通用排查流程

1. **确认影响面**：是否影响用户？影响哪些功能？是否已触发告警？
2. **止血**：必要时切换流量 / 重启 / 隔离，优先恢复服务。
3. **定位**：按「网络 → 系统 → 应用 → 数据」逐层排查，看日志与指标。
4. **根治**：找到根因并修复，避免只是重启后问题复现。
5. **复盘**：记录时间线、根因、处置，更新本文档。

## 常见故障对照

### 服务无法访问

| 排查项 | 检查方式 |
| --- | --- |
| 服务进程是否存活 | `systemctl status <服务名>` / `ps -ef` |
| 端口是否监听 | `ss -tlnp` |
| 防火墙是否拦截 | `firewall-cmd --list-all` / 安全组规则 |
| 是否资源耗尽 | `free -h`、`df -h`、`top` |
| 上游/依赖是否正常 | 数据库、网关、对象存储连通性 |
| 近期是否变更过 | 查发布记录 / 变更日志 |

### 数据库连接失败

| 排查项 | 检查方式 |
| --- | --- |
| 数据库进程与端口 | 服务状态、监听端口 |
| 连接数是否打满 | 查看最大连接数与当前连接 |
| 网络连通性 | `ping` / `telnet` 到目标端口 |
| 账号与权限 | 核对账号是否被锁定 / 权限被回收 |
| 磁盘 / 慢查询 | `df -h`、慢查询日志 |

### 磁盘空间不足

1. 定位占用：`df -h` 找到满的挂载点。
2. 大文件排查：`du -sh /路径/* | sort -hr | head`。
3. 清理日志 / 临时文件 / 过期备份。
4. 若为业务增长，扩容或归档，并设置磁盘告警。

### 网站/应用响应慢

| 层级 | 排查点 |
| --- | --- |
| 网络 | 延迟、丢包、CDN 命中率 |
| 应用 | CPU、内存、慢请求、GC / 线程 |
| 数据库 | 慢查询、连接池、锁 |
| 外部依赖 | 第三方 API 延迟 |
