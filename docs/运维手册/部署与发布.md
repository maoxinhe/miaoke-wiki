# 部署与发布

本节约定团队的发布流程。目标是：**发布可重复、可回滚、可审计**。

## 发布流程（标准）

1. **准备**：确认代码合并到发布分支，通过测试；记录本次发布内容（版本号 / 变更清单）。
2. **备份**：涉及数据变更时先备份数据库或关键配置。
3. **构建**：使用统一的构建流程（如 CI/CD），确保产物可复现。
4. **发布**：按环境顺序 `测试 → 预发（如有） → 生产`。
5. **验证**：发布后执行冒烟检查，确认核心功能正常。
6. **回滚预案**：明确回滚到上一版本的操作步骤与触发条件。

## 环境与版本规范

- 分支策略：`main` 为稳定分支；功能分支开发后经评审合入。
- 版本号：遵循语义化版本 `主版本.次版本.修订号`，发布时打 Tag。
- 生产变更需审批，禁止未经批准的私自发布。

## 发布检查清单

- [ ] 代码已评审并合并
- [ ] 测试用例通过
- [ ] 数据备份完成（如涉及）
- [ ] 变更清单已登记
- [ ] 回滚预案已确认
- [ ] 发布后冒烟验证通过

## 回滚操作（通用）

1. 停止新版本服务或切换流量。
2. 恢复上一版本的构建产物 / 镜像。
3. 数据回滚需依据备份，先在小环境演练。
4. 记录回滚原因与时间。
