# 监控与告警

> 目标：**先于用户发现问题**。监控覆盖面不足比没有监控更危险，请按清单逐项补齐。

## 监控对象

| 类别 | 建议指标 | 状态 |
| --- | --- | --- |
| 服务器 | CPU、内存、磁盘、负载、进程 | 待接入 |
| 网络 | 带宽、连通性、延迟、丢包 | 待接入 |
| 服务 | 存活、响应时间、错误率、队列积压 | 待接入 |
| 数据库 | 连接数、慢查询、主从延迟、磁盘 | 待接入 |
| 业务 | 关键转化、异常订单、风控触发 | 待接入 |

## 告警分级与值班

| 级别 | 示例 | 响应要求 |
| --- | --- | --- |
| P0 紧急 | 服务不可用、数据丢失 | 立即处理，最高优先级 |
| P1 高 | 核心功能异常、容量告急 | 30 分钟内响应 |
| P2 中 | 非核心异常、指标超阈值 | 当日处理 |
| P3 低 | 告警噪音、优化建议 | 排期处理 |

- 告警必须有 `值班表` 与 `升级机制`：值班人未响应 → 升级到负责人。
- 告警通道：企业群 / 邮件 / 电话（待配置），确保告警不被静默。

## 值班响应流程

1. 收到告警 → 判断级别与影响面。
2. 先止血（必要时切换流量 / 隔离实例），再定位根因。
3. 记录时间线、现象、处置动作。
4. 处置完成后复盘，更新监控规则与文档。
